# 捕获规则

这是 c-capture 与 o-review 共用的唯一规则真源。所有路径均相对于 Vault 根目录。

## 1. 类型标签（必选 1 个）

先看显式类型标签；没有显式标签时，再按关键词触发表识别。类型标签只选一个，其他标签可以叠加。

### 显式标签

| 标签 | 含义 |
|---|---|
| #task | 要执行的任务 |
| #waiting | 正在等待他人或外部结果 |
| #someday | 将来/也许再做 |
| #topic | 视频或内容选题 |
| #idea | 产品、工具或独立开发想法 |
| #record | 日常记录、事实或经历 |
| #insight | 洞察、反思或可复用模式 |
| #pause | 间隙记录（Interstitial Journaling） |

### 关键词触发

没有显式类型标签时，按下表识别。#waiting 的关键词必须包含等待对象或等待结果，不把裸字「等」当作触发词。

| 关键词或表达 | 识别为 |
|---|---|
| 要、需要、记得、提醒、明天、下周、别忘 | #task |
| 选题、视频、可以拍、可以做期、内容 | #topic |
| idea、产品、工具、可以做个、SaaS、App | #idea |
| 今天、刚才、发生、经历、遇到 | #record |
| 发现、原来、想明白、规律、洞察 | #insight |
| 等待、等他、等她、等客户、等回复、等确认、等消息、等审批、等反馈、等通知、提交后等、发送后等 | #waiting |
| 以后再说、将来、有空、改天、也许、或许、可能、想研究、想学、感兴趣、看到别人在做、好像不错 | #someday |
| 刚完成、做完了、接下来、下一步、分心了、回去工作、完成了、切换到、转去做、休息一下、暂停、歇会 | #pause |

## 2. 领域标签

领域标签可选且可以叠加。优先读取 60-Memory/tag-mapping.md：按其中每个「## #tag 领域名」下的「关键词：」识别当前用户配置。文件不存在或没有命中时，使用默认表。

| 默认关键词 | 标签 |
|---|---|
| 视频、自媒体、选题、拍摄、剪辑、发布 | #media |
| 产品、独立开发、SaaS、上线、用户、App、工具 | #indie |
| 生活、家、个人、健康、运动、财务 | #life |
| 学习、课程、书、读书、培训、知识 | #learning |
| 客户、外包、项目、甲方、交付、需求、合同 | #outsourcing |

动态映射优先于默认表；默认表只作为缺省配置，不覆盖用户已经编辑的映射。

## 3. 状态标签

状态标签可选，按内容价值和紧迫程度叠加：

| 条件 | 标签 |
|---|---|
| 有视频价值 | #可做视频 |
| 需要深入研究 | #待深挖 |
| 紧急事项 | #紧急 |
| 需要用户确认、无法安全判断 | #待确认 |

## 4. 项目归属

项目关联使用以下任一形式：

- @项目名：捕获阶段保留文本标记，分发时转换为 [[项目名]]。
- [[项目名]]：直接使用 Obsidian wiki-link。

验证项目是否存在时，检查 10-Projects/{项目名}.md 或 10-Projects/{项目名}/README.md。项目不存在时询问用户是否创建，不要擅自新建项目。若任务没有领域标签，从项目 frontmatter 的 area: 推断领域；项目 frontmatter 的规范见 vault-structure/references/file-templates.md。

示例：

~~~text
完成导出功能的单元测试 @物流系统
→ - [ ] 完成导出功能的单元测试 [[物流系统]] #outsourcing 📅 2026-01-12
~~~

## 5. Someday 判断条件

出现显式 #someday 时直接按 Someday 类型处理。没有显式标签时，只有同时满足以下 4 条，才建议将内容放入 someday：

1. 领域不匹配主线（读取 60-Memory/profile.md 判断主线）。
2. 没有项目关联。
3. 没有明确截止日期，或截止日期在 30 天以后。
4. 命中 §1 的 Someday 关键词。

这是建议，不是自动确认；交互模式下需让用户确认。--auto 模式不把仅因建议产生的内容送入 someday。

## 6. 间隙记录

间隙记录优先于普通类型识别：内容命中以下任一模式时识别为 #pause，并直接写入当日日记，不进入 00-Inbox/capture.md。

### 触发模式

| 模式 | 示例 |
|---|---|
| 刚完成 xxx，接下来 yyy | 刚完成文章初稿，接下来准备开会 |
| 完成了 xxx，下一步 yyy | 完成了报告，下一步是测试 |
| xxx 做完了，接下来 yyy | 代码做完了，接下来写文档 |
| 分心了、又刷了、跑偏了 | 又刷了 20 分钟，该回去工作了 |
| 回去工作、继续干活 | 回去工作，继续整理笔记 |
| 切换到、转去做 | 切换到报价单，转去做会议准备 |
| 休息一下、暂停、歇会 | 先休息一下再继续 |

### 情绪识别（唯一规则表）

这是全插件唯一的五档情绪规则表；其他 skill 只引用本节，不复制情绪关键词。

| 关键词 | 情绪标记 |
|---|---|
| 顺利、不错、搞定、完美、提前 | 😊 顺利 |
| 一般、正常、还行 | 😐 一般 |
| 卡住、困难、问题、bug、搞不定 | 😔 卡住 |
| 专注、心流、沉浸、高效 | 🎯 专注 |
| 分心、刷、跑偏、浪费、又 | 📱 分心 |

### 写入格式与位置

从内容中提取完成项、感受和下一步；无法提取时保留原文并标记待补充。写入当日日记 00-Inbox/{YYYY-MM-DD}.md 的「## 间隙日志」区块，区块不存在时创建在日记标题之后。新记录放在区块最前面，最新在上。

~~~markdown
### HH:MM
- **完成**: {刚完成的内容}
- **感受**: {emoji} {感受描述}
- **下一步**: {下一步内容}
- **备注**: {备注内容，如果有}
~~~

## 7. 分发目标

o-review 按类型标签执行分发；普通目标中的新条目采用倒序追加，即插入目标文件已有内容之前或当前月份分组的最前面，历史条目不重排。新建 topic、idea 文件使用 vault-structure/references/file-templates.md 中的模板。

| 类型标签 | 分发目标 |
|---|---|
| #task | 50-GTD/active.md |
| #task + 延后 | 50-GTD/someday.md |
| #waiting | 50-GTD/waiting.md |
| #someday | 50-GTD/someday.md |
| #topic | 20-Areas/media/topics/{选题名}.md |
| #idea | 20-Areas/indie/ideas/{产品名}.md |
| #record | 00-Inbox/{日期}.md |
| #insight | 60-Memory/patterns.md，按 vault-structure/references/memory-model.md 的 L3 条目格式 prepend |
| #pause | 捕获时直接写入当日日记的「## 间隙日志」，不进 capture.md |

#task + 延后需要用户确认；#waiting 保留等待对象；@项目名在任务写入时转为 wiki-link；已完成任务由 o-review 归档至 50-GTD/done.md。

## 8. 置信度分级

置信度针对类型判断，而不是针对领域或状态标签：

- 高：用户明确写出一个显式类型标签。
- 中：恰好命中一类关键词，且不满足 §5 的 Someday 四项条件。
- 低：命中多类关键词，或没有命中任何类型关键词。

o-review --auto 只分发高置信度和中置信度内容。低置信度内容保留在 00-Inbox/capture.md，加上 #待确认，等待交互模式确认；自动模式不猜测、不建项目、不因建议进入 someday。

## 9. 日记 vs 周记边界

日记是输入，周记是加工：

| 日记 | 周记 |
|---|---|
| 实时捕获、流水账 | 本周回顾与反思 |
| 间隙记录（#pause） | 项目进展评估 |
| 情绪和感受 | 下周规划与优先级 |
| 快速想法 | 模式识别、洞察提炼 |
| #record 内容 | o-weekly 生成的周总结 |

#record 必须写入 00-Inbox/{日期}.md；#pause 必须写入当日日记的间隙日志；流水账和随手记留在日记。周记只包含 o-weekly 生成的周总结、手动添加的周级规划，以及从日记提炼的 #insight。不把日常记录或间隙记录直接写入周记。
